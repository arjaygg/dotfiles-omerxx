# Frozen Spec — Goal 05 Step 15: unattended-safety delta

Branch/worktree label: `native-agent-orchestration-step15`
Base: `main` (currently `ecb66b6`). Steps 1–14 and 16 are merged; nothing is outstanding.

<intent-contract>
Make the harness safe to run with nobody watching. Three deliverables, one theme — **a run that
stops must leave a durable, machine-readable trace of why**:

1. `.claude/workflows/orchestrate.js` gains an unattended path: triage per §23, the three
   persisted loop counters per §24, the computed follow-up signal per §25, and a HALT protocol
   per §15 that writes a terminal status on **every** exit — including the degenerate cases
   where the spec path is unknown or ambiguous.
2. `ai/skills/cap/references/schemas.md` gains the §20 finding fields.
3. `ai/skills/auto-ship/SKILL.md` is reconciled with §15 so its unattended legs write the same
   terminal status.

Unattended does **not** mean backgrounded. Per §13, `Workflow` remains usable unattended because
`agent()` inside a script is a synchronous await and the script *is* the run; what is forbidden
is ending a turn on a backgrounded call, because no event loop exists to resume it. The
acceptance criterion `grep -nE 'run_in_background|detached'` → no match on unattended paths is
the mechanical expression of that rule, not a ban on the `Workflow` tool.

Step 14's ≤3 literal subagent call-site cap still binds. The existing `runStage()` funnel means
new stages cost zero additional sites; keep it that way.
</intent-contract>

## Task

Step 14 shipped the interactive skeleton (PR #383, `14a2ec7`). This step adds the delta that
makes the same script survive a cron, CI, or `/loop` invocation where nobody reads chat output.

### 1. `.claude/workflows/orchestrate.js`

**Triage (§23).** Implement the five-category taxonomy — `intent_gap`, `bad_spec`, `patch`,
`defer`, `reject` — with its two tie-breakers (in doubt between `bad_spec` and `patch` prefer
`bad_spec`; unsure between `defer` and `reject` prefer `reject`) and the cascade (any
`intent_gap` moots everything below it; any `bad_spec` moots `patch` findings).

The **scope-authority rule** is the subtle part and the one the fixture below targets: a finding
may be routed `defer` or `reject` *as out of scope* **only on the authority of the intent
itself**. The spec's own scope language, the plan, and the shape of the diff are **not**
admissible authorities. If only those exclude a finding, that is evidence against the current
reading — route `intent_gap` or `bad_spec`, never `defer`.

**Loop bounds (§24), all three, all persisted to the spec's frontmatter.** An in-context counter
resets silently at compaction, on a crash, or on a resumed cron run, and the loop then runs
forever:

| Loop | Bound | Counter | Terminal condition |
|---|---|---|---|
| Schema-invalid retry | 3 | `retry_count` | convert to `blocked` |
| Doubt cycle | 3 | `doubt_cycle_iteration` | escalate — do not raise the bound; decompose instead |
| `bad_spec` re-derivation | 5 | `review_loop_iteration` | HALT `blocked`, condition `review repair loop exceeded 5 iterations (non-convergence)` |

Also implement the worker-outcome states, which are distinct from finding categories: `error`
(worker died or returned `null`) → retry once, then surface; `retry` (schema-invalid or
`valid: false`) → the bounded loop; `blocked` → HALT and escalate with a concrete unblock path.
A null or empty return is a failure, never a success.

**Review Triage Log (§24).** Append one entry per pass to the spec's `## Review Triage Log`:
counts per category broken down by severity, plus an `addressed_findings` list (or `none`), so a
pass that fixed nothing is visibly a pass that fixed nothing.

**Follow-up signal (§25).** Computed, never judged: `followup_review_recommended` is true if any
`patch`-triaged finding is `high`, **or** if `3 × medium_count + 1 × low_count >= 5`. It counts
only `patch` findings — never `defer`, never `reject` — and is written to frontmatter along with
the counts and the score.

**HALT (§15).** Every exit path writes a terminal status to a durable artifact before stopping.
Minimum payload: `status ∈ {done, blocked}`, the blocking condition in one line, and the artifact
path. Written to the spec's frontmatter, or to a fallback result file when the spec path is
unknown. Follow the plan's insistence on deterministic degenerate paths: an unresolvable spec id
lands at `<id>-unresolved.md`, an ambiguous on-disk match at `<id>-ambiguous.md` — deliberately
**not** a third title-derived filename that could collide with either candidate.

Note the constraint this creates: a workflow script has no filesystem access, so the write-back
must be performed by the stage agent (which does) or by the invoking Coordinator. Decide which,
state it in a comment, and make the dry run prove the chosen path.

**Severity.** The Coordinator assigns `low`/`medium`/`high` during triage. Reviewers never do —
§20 is explicit that a reviewer sees one artifact through one lens and cannot know consequence
for the artifact's consumer.

asserts that every schema-required key has a matching fixture field. A rename breaks all three
together; they must move in one commit.

Also carry over §20's dedupe rule if it is not already stated: dedupe only findings with the same
claim **and** the same required action, then evaluate each survivor independently — do not reject
a finding because a related finding was rejected.

## Constraints

- **Anti-nesting:** implement directly. Do not spawn subagents — the session's standing
  instruction forbids the Agent tool unless the user asks, and no acceptance criterion needs a
  live multi-agent run. Fixtures and dry runs are the check.
- Do not raise any §24 bound to make a test pass. If 3 doubt cycles feel insufficient, the
  artifact is too big — decompose it. Raising the bound is the failure mode the section names.
- Branch `chore/native-agent-orchestration-step15` in its own worktree under `.trees/`.
  Never commit to `main`; `protect-main.sh` blocks it anyway.
- Commit via `~/.dotfiles/scripts/ai/commit.sh`. Raw `git commit` is hook-blocked.
  `atomic-status.sh` is blocked by the lean-ctx shell allowlist in this session type — check
  thresholds with `git status --short` (≤7 files, ≤3 subsystems, ≤300 diff lines). The schema
  rename touches three files at once; if the diff overruns, split by concern, not by file.
- Native `Edit`/`Grep`/`Glob` are denied. Use `ctx_shell`/`ctx_read`/`ctx_search`, and `Write`
  for whole files. To rewrite an existing file, `rm` it first — `Write` refuses to overwrite a
  file this session has not read.
- `python3 -c` and interpreter heredocs are blocked. Write a script to the scratchpad and run it.
  Note also that `tee` is not in the shell allowlist and piping to `head`/`tail` after a command
  is hard-blocked; put multi-step shell work in a scratchpad `.sh` and run it with `bash`.
- **Run `stack merge` from `~/.dotfiles`, and expect it to fail on local branch deletion while
  this worktree still exists.** Observed on both PR #383 and #385: the remote squash-merge
  succeeds, then the script errors and skips the stack update. Verify with
  `gh pr view <n> --json state` before treating the error as a real failure.
- Before finishing, run all three gates and paste their output:
  `python3 scripts/validate_skills.py`, `python3 scripts/run_evals.py --summary`,
  `python3 -m unittest` over the test file.
