# Frozen Spec — Goal 05 Step 17: Tier 4 input sensitivity

Branch/worktree label: `native-agent-orchestration-step17`
Base: `main` (currently `abc1ee8`). Steps 1–16 are merged; only 17 and 18 remain.

<intent-contract>
Add the fourth eval tier: **does an optional input steer a skill by the intended amount?**

Tier 4 varies **one** optional input against a **fixed flawed artifact** and grades
*distribution and balance across concerns*, not finding count. The three shapes that matter:
a vague input should shift almost nothing; a single item should influence without dominating;
contradictory items should be handled gracefully rather than crashing or collapsing to one
concern.

`lensed-review` is the subject because its optional steer is the one every other skill's steer
resembles, and because Step 10 made it the repo's single review mechanism.

The load-bearing assertion is comparative, not absolute: **the vague-input case must shift the
distribution less than the specific-input case.** An absolute threshold would encode one model's
verbosity; a comparison between two runs of the same model on the same artifact does not.

Tier 4 costs tokens and runs on demand — never in CI. It must not become a hidden dependency of
`--summary`, which the commit hook runs on every commit.
</intent-contract>

## Task

### 1. Fixed flawed artifact — `evals/fixtures/lensed-review/`

A small, deliberately flawed source file that gives every declared concern something real to
find, so a distribution is measurable rather than an artifact of one lens having nothing to say.
One flaw per concern is enough; make each unambiguous:

- correctness — a wrong result on a reachable path
- security — untrusted input reaching a sensitive sink
- resilience — an unbounded wait, missing timeout, or unhandled failure
- style — a naming or structure problem that is only cosmetic
- doubt — a confident comment or docstring the code contradicts

Keep it under ~60 lines. A large artifact makes the grader's job noisy and the shift metric less
stable. Note that `evals/fixtures/` already holds six skills' fixtures — follow their layout.

### 2. Case format — `evals/cases/lensed-review.json`

Add a `sensitivity` block alongside the existing `trigger` and `evals` keys. Nothing validates
this file's schema today (checked: no validator references `evals/cases`), so the shape you
choose is the shape — pick one a reader can extend to a second skill without guessing:

- the artifact path, relative to the fixture dir
- the concern vocabulary the distribution is measured over
- the four cases, each with an `id` and its steer: **baseline** (no steer), **vague**,
  **single-item**, **contradictory**

The baseline case is the reference distribution; the other three are compared against it.

### 3. `--sensitivity` — `scripts/run_evals.py`

Follow the Tier 3 mechanics already in this file rather than inventing a parallel harness:
throwaway git repo seeded from the fixture dir and committed as baseline; headless `claude` with
an explicit permission mode and pre-approved tool list; the trace graded by a second `claude -p`
call with the trace **fenced as untrusted data and piped over stdin, never argv**; grader output
validated as JSON before write; results under `evals/results/`.

What differs from Tier 3:

- The grader returns a **distribution** — a count per concern — not a pass/fail. Its preamble
  must carry the same untrusted-data fencing language as `GRADER_PREAMBLE`, and must instruct
  the grader to count findings per concern and nothing else. It assigns no severity and makes no
  judgement about whether the steer was obeyed; that is computed.
- The verdict is computed from the distributions, not asked for. Normalise each distribution and
  measure shift from baseline — total-variation distance (half the L1 distance between the two
  normalised vectors) is the natural choice: bounded 0–1, symmetric, and interpretable as "the
  fraction of attention that moved."
- Assertions:
  - `vague_shift < single_item_shift` — **the plan's named criterion.** Report both numbers.
  - the single-item case influences without dominating — its steered concern gains share but
    does not take all of it.
  - the contradictory case still produces a valid, non-empty distribution — graceful, not a
    crash and not a collapse to one concern.
- A missing `claude` CLI is a **failure**, not a silent skip — mirror how `run_behavioral_cases`
  already handles `FileNotFoundError` and `TimeoutExpired`.

Wire `--sensitivity` as its own branch in `main()`, parallel to `--behavioral`, returning before
the Tier 2 path. It must not run as part of the default or `--summary` invocation.

### 4. Tests — `scripts/test_run_evals_sensitivity.py`

The live tier needs the `claude` CLI and tokens, so it cannot run in CI. Everything decidable
without a model call must still be tested:

- the shift metric: identical distributions → 0; disjoint → 1; symmetry; a hand-computed
  mid-range case
- normalisation of an all-zero distribution does not divide by zero
- the comparative assertion fires when `vague_shift >= single_item_shift`
- the dominance check fires when one concern takes the entire distribution
- the contradictory case fails on an empty distribution
- the case file parses, declares all four case ids, and its artifact path exists on disk
- `--sensitivity` is absent from the default and `--summary` paths (a token-spending tier must
  not be reachable from the commit hook)
