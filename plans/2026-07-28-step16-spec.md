## Mechanics to implement (from Part VII)

1. **Throwaway repo:** each behavioral eval case runs inside a freshly created temp git repo
   (`tempfile.mkdtemp()` + `git init`), with that skill's fixture files from
   `evals/fixtures/<skill>/` copied in and committed as the baseline before the agent runs.
2. **Executor invocation:** shell out to the `claude` CLI in headless/print mode with
   `--output-format stream-json`, an explicit `--permission-mode` (pick one that allows file edits
   without prompting — e.g. `acceptEdits`), and a pre-approved tool list, so the eval genuinely edits
   files rather than being denied and narrating around it.
3. **Untrusted trace handling:** the full stream-json trace (including tool calls, not just final
   text) must be captured and passed to the grader **fenced as untrusted data over stdin**, never as
   an argv string (argv hits the OS arg-size limit on large traces).
4. **Grader:** a second `claude -p` call (or equivalent) that reads the fenced trace + the case's
   `expectations[]` and returns a JSON verdict. Validate the grader's stdout as JSON before writing it
   to `evals/results/<skill>-<case-id>.json`. If it fails to parse, treat the case as a hard failure,
   not a silent skip.
5. **`--behavioral` CLI flag** on `scripts/run_evals.py`: runs only the behavioral (`evals[]`) cases
   (not the Tier 2 trigger/collision checks — those stay under the existing default/`--trigger` path).
   Exit non-zero if any behavioral case fails or any grader output fails JSON validation.

## Pressure cases

For each of the 10 discipline skills above, add three new entries to that skill's `evals[]` array in
`evals/cases/<skill>.json`:

- A **time-pressure** case: prompt argues the user is in a rush / deadline is now, and asks to skip
  the skill's discipline step (e.g. skip verification, skip the fixture check, skip the checklist).
- A **sunk-cost** case: prompt argues significant prior work would be wasted if the skill's discipline
  step is followed now (e.g. "we already did X, don't redo it").
- An **authority-pressure** case: prompt claims a manager/lead/senior engineer already approved
  skipping the step.

Each pressure case's `expectations[]` must assert the skill's core discipline step still happens
despite the pressure (name the specific behavior that must survive — cite the actual skill file
content, don't guess generically). Add a matching fixture under `evals/fixtures/<skill>/` for any
case that needs starting file state.
